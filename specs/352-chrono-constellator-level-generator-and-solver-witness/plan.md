# Implementation Plan: R02-G06-02 — Chrono Constellator: level generator and solver witness

## Summary

Extend `ChronoConstellatorCore` (feature 351) with the 100-entry manifest, a band-profiled generator, the integer-tick
phase-search solver with its lower-bound proof, difficulty metrics, versioned witness files and the catalog digest, on the
pattern of Colorfall Canyons's feature 342. Research: [research.md](research.md). Data: [data-model.md](data-model.md).
API: [contracts/api.md](contracts/api.md). Quickstart: [quickstart.md](quickstart.md).

## Technical Context

**Language/Version**: Swift 6. **Primary dependencies**: ChronoConstellatorCore's own types (`ChronoConstellatorLevel`,
`ChronoConstellatorTimeline`, `ChronoConstellatorEvaluation`, `ChronoConstellatorPlay`, `ChronoConstellatorRules`);
VisualCoreSimulation (`SeededRandom`, `SeedDerivation.derive(_:index:)`, `PuzzleCatalog.digest(id:identities:)`,
`ProgressionRule`); VisualCoreMath (`StableHash`). No GPU, GLSL, Objective-C++ or UIKit code; no new package or target.
**Seeds**: level n uses its manifest seed; candidate k draws from `SeededRandom(seed: SeedDerivation.derive(seed, index:
k))`, k = 0 … 511. Brute-force cross-checks use seed 2_352.
**CPU reference**: every witness timeline is replayed through R02-G06-01's `ChronoConstellatorPlay` (closed-form
positions and the kernel's evaluation); the solver's window check uses the same `ChronoConstellatorTimeline.positions`.
**Testing**: `swift test --package-path Packages/ExperiencesRound02 --filter ChronoConstellator` (CI step exists).
**Performance**: the solver scans T = 1 … tick limit (≤ 360 at generation) for m(T) (≤ 5 stars each) and checks each window
over ≤ T ticks: ≤ 360 × 5 + 360 × 360 × 5 ≈ 650,000 position look-ups per candidate; the Python prototype certified all 100
levels in 0.3 s. Catalog tests are split by band so each stays under 10 s on a debug host build.
**Constraints**: additive to R02-G06-01's public API; budget = the manifest move budget (8 … 19); every value an exact
integer; no network, no art; witness files written only with `CHRONO_CONSTELLATOR_WRITE_WITNESSES=1`.

## Parallel work

The lead writes the error cases, the manifest, the solver, the difficulty and the generator (coupled through the solver's
acceptance); agents A (solver tests with an independent brute force), B (witness and its tests) and C (generator tests)
then work in parallel against the contract; the lead writes the catalog tests and the witness files, retests every agent
result and records checks only after every agent has reported.
