# Implementation Plan: R02-G09-02 — Nocturne Garden: level generator and solver witness

**Branch**: `382-nocturne-garden-level-generator-and-solver-witness` (spec directory only; work on `main`) | **Date**:
2026-11-22 | **Spec**: [spec.md](spec.md)

## Summary

Extend `NocturneGardenCore` with the content pipeline on the pattern of Faceted Forge's (feature 372): the 100-entry
manifest with provenance, band profiles (bed, sizes, elevations, bloom count, forbidden ring, required match, leak
allowance, decoy), a seeded candidate generator that builds the target from its own blooms, a depth-first solver that
finds a winning sequence of exactly the lower bound of clarification Q2 (a sun move if needed plus ⌈needed / cover⌉
plants) with coverage pruning and counted work, difficulty metrics, witness files with per-action mask digests and the
near miss, the catalog digest and the progression check. Research: [research.md](research.md). Data:
[data-model.md](data-model.md). API: [contracts/api.md](contracts/api.md). Quickstart: [quickstart.md](quickstart.md).

## Technical Context

**Language/Version**: Swift 6. **Primary dependencies**: VisualCoreSimulation (`SeededRandom`, `SeedDerivation`,
`PuzzleCatalog`, `ProgressionRule`, `PuzzleDifficulty`) and VisualCoreMath (`StableHash`). No GPU or UI code; no new
target.
**Numbers**: a level has at most 7 supplied blooms; a plant candidate set is at most 6 kinds × 3 sizes × 768 anchors
before filtering to plants that touch the target; work is counted in plant evaluations (bound 20,000 per level).
**Seeds**: candidate k of entry n uses `SeedDerivation.derive(plannedSeed, index: k)`; fixtures seed 2_382.
**Testing**: `swift test --package-path Packages/ExperiencesRound02 --filter NocturneGarden`; catalog tests in groups of 5.
**Performance**: measured per group locally (under 10 s on a debug host build); not asserted on CI.
**Constraints**: additive; R02-G09-01's types unchanged except two new error cases; witness files written only with
`NOCTURNE_GARDEN_WRITE_WITNESSES=1`.

## Parallel work

The lead writes the error cases, the manifest, the solver, the difficulty and the generator; agents A (solver tests
with an independent check), B (witness and its tests) and C (generator tests) then work in parallel against the
contract; the lead writes the catalog tests and the witness files, retests every agent result and records checks only
after every agent has reported.
