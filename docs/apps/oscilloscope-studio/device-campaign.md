# Oscilloscope Studio — device campaign plan

**Status: nothing measured on a device.** Every result below is pending. Feature 065 (A08-P05), FR-A08-530, task
T-A08-512; completed and extended in A08-P06. Oscilloscope Studio (`a08.oscilloscope-studio`) is measured as a row of
the one VisualCore app's device campaign (Auto-Creator.md section 23), not as a separate app. Simulator results,
including the accuracy audit (`ScopeAccuracyAuditTests`), the two-channel microphone suite with its capture double
(`StereoMicrophoneAudioSourceTests`), the quality and announcement suites (`ScopeQualityTests`,
`ScopeAnnouncerTests`) and the shared microphone recovery suites of `VisualCoreAudio`, are development signals only and
never device evidence; their routes, interruptions and route changes are simulated.

## When and in which order

1. Not before the gate `ImplementationLock-100` is recorded: `python3 scripts/migration_ledger.py guard-device` must
   exit 0. No install, launch or test of the app on a physical device happens earlier.
2. The owner has provisioned signing, paired, trusted and unlocked the devices and answers every system prompt that
   needs a person (owner steps; otherwise the row is `BLOCKED_OWNER_ACTION`). The agent never taps a permission or
   trust prompt itself.
3. Order: **D1** (iPhone 15), then **D2** (iPad Pro 13-inch M5), then **D3** (iPad A16). **D3 stays on iPadOS 26.5
   and is never updated**; if it reports another version, its campaign is blocked and the owner is told.
4. Test audio is the scope's own test signal or a synthetic tone generated by code and played from a second device or
   a file; no recorded or third-party sound is used. Hardware identifiers go only to untracked private files.
5. Every measurement uses short runs; only the thermal row lasts ten minutes, as the plan of the one app's campaign
   asks. Longer behaviour is bounded by arithmetic from the short runs.

## Measurements

The host's quality tier is clamped to the levels 0 to 2 (`ScopeQuality`): level 0 → every pixel column drawn and the
spectrum analysed every frame; level 1 → half the columns, every second frame; level 2 → a quarter of the columns,
every fourth frame. These are configured budgets, not measurements.

| Measurement | Devices | Procedure | Pass criterion | Result |
|---|---|---|---|---|
| Stereo routes | D1, D2, D3 | Choose the microphone with the built-in microphone, then a two-channel USB or Lightning/USB-C interface where available, then wired and Bluetooth headsets; read the channel count the scope reports and switch to XY | The reported channel count equals the route's input channel count (1 or 2); XY plots only with two channels and otherwise shows "XY needs two channels"; left and right are not swapped (a tone on one input moves only its axis) | pending |
| Route change while running | D1, D2, D3 | Microphone live in XY; plug and unplug the headset or interface; freeze before one change | The capture rebuilds with the new channel count and the change is spoken with VoiceOver on; a frozen window keeps its own channel count; drawing never stops | pending |
| Input latency | D1, D2, D3 | A second device plays a click; record the time from the click's onset in a reference recording to the frame in which the trace shows it, over a short run of clicks (owner-held reference) | A figure is recorded per route; the app never states a latency figure in its words | pending |
| Sample rates | D1, D2, D3 | Routes that deliver 44.1 kHz and 48 kHz; play the 1 kHz sine from a second device | The spectrum readout uses the delivered rate (peak within one bin of the played frequency, level relative to full scale) | pending |
| Frame time per view and level | D1, D2, D3 | For waveform, XY and spectrum with the test signal and with the microphone, pin the host's quality level to each level and record the frame intervals over a short run | No sustained run of dropped frames at the level the governor settles on; every lower level is at least as fast as the level above it | pending |
| Thermal state over ten minutes | D1, D2, D3 | Ten minutes in the spectrum view with the microphone live, not charging; record `PerformanceRecord.thermal`, `lowPower`, the level and the frame intervals each minute | The thermal state never reaches critical; when it rises the level steps down instead of frames being dropped | pending |
| Interruptions and permission | D1, D2, D3 | Call, alarm and Siri with the microphone live; first request, refusal, grant and revoke in Settings (owner on the device) | Same criteria as the shared microphone rows of Audio Odyssey's campaign; the test signal works at every step | pending |
| VoiceOver and announcements | D1, D2, D3 | VoiceOver on: hear the canvas description in each view and state (no signal, clipping, frozen, test signal, mono); change view, freeze, lose the trigger, clip, change route | The description names view, source, channels, timebase or readout, frozen and clipping; announcements at most one per one and a half seconds, only on changes | pending |
| Accessibility system audits | D1, D2, D3 | The system accessibility audits at the default and the largest text size with `VC_RUN_AUDITS=1` (owner ruling of 2026-11-13) | No audit issue in the Oscilloscope Studio screens | pending |

Each row is recorded pass, fail or `BLOCKED_OWNER_ACTION`; skipped is never success. No measured value of Oscilloscope
Studio is claimed anywhere until its row passes. Readouts stay "relative to full scale"; no calibrated, certified,
laboratory or medical accuracy is claimed whatever the campaign shows.
