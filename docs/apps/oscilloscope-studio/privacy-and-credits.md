# Oscilloscope Studio — privacy and credits

Oscilloscope Studio is the experience `a08.oscilloscope-studio` of the one VisualCore app (ADR-0009). It has no app
target, Info.plist or privacy manifest of its own: the app's declarations cover it. Feature 066 (A08-P06), FR-A08-601
and FR-A08-604. Sources: `Packages/ExperiencesCreative/OscilloscopeStudio` (below: OS) and the audio products
`VisualCoreAudio` (`Packages/VisualCoreRendering`) and `VisualCoreAudioDSP` (`Packages/VisualCore`).

## What is stored on the device

| What | Where | Written by | Content |
|---|---|---|---|
| Saved presets | `scope-<uuid>.json` in the experience's own storage folder, `Application Support/Experiences/a08.oscilloscope-studio/` | `OS/Experience/ScopePresetStore.swift` through `ExperienceStorage.write` (atomic replace, quota of `StorageQuota`: at most 64 files and 16 MiB) | The scope settings the person saved under a name (`ScopePreset`, format 1): the id, the name, the saved time, the test waveform and frequency, the gain, the timebase, the trigger level, slope and mode, and the view (waveform, XY or spectrum). No sound, no samples, no readouts and no file name or address |
| Saved session state | `state.json` in the same folder | the app (`SavedStateStore`, `Apps/VisualCore/App/AppModel.swift`), not the experience | The session snapshot of the core (`ScopeState`, schema 3): the source kind (test signal, file or microphone), the test waveform and frequency, the gain, the timebase, the trigger, the view, freeze and the cursor positions, so that the scope can resume. A picked file is not remembered by its contents or address; after a restore the person chooses the file again (the message "The audio file is no longer available. Choose it again, or use the test signal."). No sound |

Nothing else is persisted by the experience. The three built-in presets (Audio overview, Bass detail, Spectrum check)
are part of the code (`ScopePreset.builtIns`, ids `00000000-0000-4000-8000-0000000008A1…A3`) and are never written. Its
sources write no named defaults values (`ExperienceStorage.setValue` is not called), no other files and no
`UserDefaults` values. Damaged files, files of a newer format, files whose name does not match their id and files that
claim a built-in's id are counted and kept, never deleted or rewritten (`ScopePresetStore.reload()`;
`ScopePresetStoreTests.testDamagedNewerMismatchedAndBuiltInFilesAreKeptByteIdenticalAndCounted`,
`ScopePresetMigrationTests`). A save beyond the storage quota is refused with a plain message and changes nothing
(`ScopePresetStoreTests.testASaveBeyondTheStorageLimitIsRefusedAndChangesNothing`). Removing the app removes the
folder.

## Sound

- **No sound is stored, recorded or sent.** The samples of every source go into a fixed-size two-channel buffer in
  memory (`StereoSampleBuffer`, 16,384 frames), are read once per drawn frame into a `SignalWindow` (triggered
  waveform, XY pairs) or a spectrum transform (`SpectrumReadout`) and are then overwritten. A frozen window is held in
  memory only and is gone when the experience closes. No audio file is written, no recorder or asset writer is used
  (check `os-no-network`, T-A08-603) and presets hold no audio.
- **Test signal.** Generated by code (`TestSignalAudioSource`: sine, square or sweep, two channels with the right at
  1.5 times the left frequency); it is the first source, needs no permission and reads nothing.
- **Audio file.** The person picks a file with the system file importer (audio types only). It is read in place with
  security-scoped, read-only access (`StereoFileAudioSource`) and decoded in memory; it is not copied into the app and
  never changed. A file that cannot be decoded keeps the previous source and shows a message with the offer of the
  test signal (`ScopeSessionTests.testAnUndecodableFileKeepsThePreviousSource`). The file's name is display state only
  and is never written to the session state or to a preset.
- **Microphone.** Used only while the person has chosen it as the source, and only after the system permission was
  granted (`StereoMicrophoneAudioSource`, one or two channels as the route delivers). Choosing another source, closing
  the experience, a suspension or sending the app to the background stops the input (the presenter stops the source on
  `didEnterBackground`, on suspension and in `teardown`;
  `ScopeSessionTests.testSuspendingStopsTheSourceAndActivatingStartsItOnAFreshBuffer`). When access was never decided,
  the system is asked once; denied or restricted access keeps the previous source and shows the way to Settings with
  the offer of the test signal (`ScopeSessionTests.testADeniedMicrophoneKeepsThePreviousSourceAndOffersTheTestSignal`,
  `StereoMicrophoneAudioSourceTests.testDeniedIsRefusedWithoutCapture`). A restored microphone selection without
  access returns to the test signal.
- **Mixes with other audio.** The two-channel microphone source uses the shared session options
  (`MicrophoneAudioSource.sessionOptions`, `.mixWithOthers`; `MicrophoneSourceTests.testSessionMixesWithOtherAudio`),
  so sound the person is already playing in other apps keeps playing.
- **Readouts are relative to full scale.** Levels are shown in dBFS and as fractions of full scale, frequencies from
  the cursors or the spectrum peak; no calibration to volts or sound pressure exists and none is claimed
  (`SpectrumReadoutTests.noCalibratedWordingInAnyText`, `ScopeAccuracyAuditTests.testReadoutWordsStayRelativeToFullScale`).

## The one permission

Oscilloscope Studio uses the app's existing microphone usage string and adds no other (FR-A08-601). The app declares in
`project.yml` (`NSMicrophoneUsageDescription`, checked by `Apps/VisualCore/Tests/Unit/BundleTests.swift`):

> Listens to sound in the room to drive the visuals; audio stays on this device and is not recorded.

The app's other usage string, `NSPhotoLibraryAddUsageDescription`, belongs to A01 (Generative Art Studio); Oscilloscope
Studio does not use it.

## What is not done

- **No collection.** Nothing is sent anywhere by the experience; there is no upload, sync, accounts, sign-in or
  analytics.
- **No network.** The sources of the experience and of `VisualCoreAudio` contain no `URLSession`, `Network`, tracking,
  advertising, motion or location framework use and no audio recorder or asset writer (check `os-no-network`,
  T-A08-603). The app tracks nothing (`NSPrivacyTracking` false, no tracking domains).
- **No capture of other apps.** Only the microphone, a picked file or the test signal is analysed; the sound of other
  apps is never captured.
- **No other sensors.** The drawn columns and the spectrum analysis rate follow the quality level the host sets (level
  0 to 2, `ScopeQuality`); the host's `QualityGovernor` decides it from the thermal state and Low Power Mode (public
  `ProcessInfo` state). The experience reads neither itself.
- **No accuracy statement beyond the readouts.** No latency figure and no accuracy beyond "relative to full scale" is
  stated; the accuracy audit (`ScopeAccuracyAudit`) checks the readouts against the built-in test signal only.

## Required-reason APIs and the app's privacy manifest

The app manifest `Apps/VisualCore/Resources/PrivacyInfo.xcprivacy` declares no tracking, no collected data types and
three accessed-API categories. The experience's uses fall under them; it adds none:

| Category and reason | Use by Oscilloscope Studio |
|---|---|
| `NSPrivacyAccessedAPICategoryFileTimestamp`, `C617.1` | `ExperienceStorage` reads file attributes (`attributesOfItem`: type and size) of the experience's own files when the preset store lists, reads or writes presets |
| `NSPrivacyAccessedAPICategoryUserDefaults`, `CA92.1` | `ExperienceStorage` holds the app's `UserDefaults` for named values under the prefix `exp.a08.oscilloscope-studio.`; Oscilloscope Studio stores none |
| `NSPrivacyAccessedAPICategorySystemBootTime`, `35F9.1` | Frame times and quality decisions come from the app's render host (`ExperienceSession`); the experience's sources read no boot time. Elapsed time inside the app only |

The built product is checked against this manifest by `release_check.py --only app-release-build
app-privacy-manifest app-no-tracking app-usage-descriptions` ([build-and-archive](../../release/build-and-archive.md)).

## Credits

- **Code.** The experience's sources, including the acquisition and trigger (`OS/Core/ScopeAcquisition.swift`), the
  traces (`ScopeTrace`), the spectrum view and readout (`SpectrumView`, `SpectrumReadout`), the cursors and zoom
  (`ScopeReadout`, `ScopeZoom`) drawn through the host's renderers, and the audio products `VisualCoreAudio` and
  `VisualCoreAudioDSP` (buffers, test signal, spectrum transform, decimation) are this repository's own code. The
  experience depends only on the local packages `Packages/VisualCore` and `Packages/VisualCoreRendering`
  (`Packages/ExperiencesCreative/Package.swift`); it adds no third-party package. The app's third-party components
  (ANGLE and the libraries inside it, listed in `docs/legal/third-party.json`) are bundled under the app's `Licenses`
  folder, shown in the app's Acknowledgements and checked by `app-licenses`.
- **Assets.** None. The grid, the traces, the spectrum, the colours and the test signals (sine, square, sweep) are
  generated by code; no third-party art, font, sound or data is used. The test audio of the suites is synthetic and
  generated by the tests themselves; the committed preset fixtures are resources of the test target only, and
  `scenario-manifest.json` is outside every target's path. No image, sound or model is bundled.
- **ProjectM.** Not used; no engine code, preset format or name of it is in the experience, and ProjectM types stay out
  of the app.
